## Purpose
After this node a pin's mutation patch never lands in the node's own worktree. D18 tells sessions that a script repeating the tests applies each mutant in a scratch copy of the tree, never in the node's own worktree, and checks the worktree with `git status` afterwards, because a trap that restores a mutated file does not run on SIGKILL or an out-of-memory kill. A08's pin check is the same kind of run (apply a deliberate break, show a case fails, take the break out again), but the node skill, the tester and the reviewer say "with the patch applied" and "with it reverted" without saying where, which reads as "in the worktree". After this node they say the patched runs happen in a scratch copy of the tree, as D18's rule says for sweeps, and that the node's worktree is clean afterwards; this repository's own tester and reviewer agents say the same.

## Changes

2. **The plugin's tester and reviewer.** The tester's pin instructions say a mutation it tries before the handoff is tried in such a copy, never in its worktree, and its worktree is clean before the pin commit. The reviewer's pin check reads the copy and the `git status` from each `pin-<n>.log`, treats a patch applied in the node's own worktree as a finding, and runs any check of its own in such a copy. *D21-AC-2.*
3. **This repository's agents.** `.claude/agents/noodlebot-tester.md` and `.claude/agents/noodlebot-reviewer.md` get the same line for a pin's mutation patch. *D21-AC-3.*

## Risks
- D18's `bounded-tests.test.sh` (at its PR's head `1e916c6`) reads, in each file it checks, the first paragraph or bullet that holds the words `scratch copy` as that file's bounded-run rule. In `plugin/skills/node/SKILL.md`, `plugin/agents/tester.md` and `.claude/agents/noodlebot-tester.md` the pin wording comes before that rule, so pin wording there that holds those two words would become the unit D18's test reads and fail it. The node checks D18's test as merged and words the pin lines so it still passes (for example by naming "a copy of the tree outside the node's own worktree", or by pointing to the bounded-run rule), never by changing a line of D18's test.
- A08's strict checks in `skill.test.sh` pin whole sentences of the reviewer's pin check (`the three runs show the pinned cases pass at the pin commit, the named case fails with the patch applied and they pass again with it reverted`) and of the skill's frozen pin lines; the new wording is added beside them, not written into them.
- A scratch copy made with `cp -a` of the worktree keeps its `.git` file, so a commit made in the copy lands on the node branch (D18's stray `base` commit); a copy of the pin commit's tree (for example `git archive` of it, or a detached worktree) does not. The node may say so; it is the session's to work out.
- The rule is wording: a session can still ignore it; the reviewer's check of each `pin-<n>.log` is what catches it, and S12's memory ceiling is what holds when a run is killed.
- This repository has no imported nodes, so its own agents' pin line is used only if one is imported later; it is there so the plugin's agents and this repository's say the same.
