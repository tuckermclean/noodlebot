# W06 — site-design

| Track | Deps | Unlocks | Size |

**Owns:** the presentation of the status site: `site/style.css` (the colour tokens, both themes, the layout), the head of `site/index.html` (theme colour, favicon), the markup and classes of the views in `site/views.js` and of the explorer's drawing in `site/explorer/view.js` (cards, badges, meters, the timeline, the chart's grid, the state colours), the change mark in `site/app.js` and `site/views.js`, and their tests `site/test/design*.test.mjs`.
**Resolves:** #88

## Purpose
After this node the status site looks designed rather than merely working. One set of colour tokens drives a light and a dark theme that follow the reader's system setting, and their text meets WCAG AA contrast. Each node state has one colour, used alike by the explorer, the node table and the repositories view. Every view sits in a page shell with a header, the current route marked and a live or stale pill. The repositories are cards, each with a bar of its node states. The throttle shows meters with reset countdowns and a gridded history chart. The activity is a timeline grouped by day, with state badges. What changed since the last poll is marked for a moment, and the layout works on a phone. The site stays as W03 made it in every other way: plain HTML, JavaScript modules and CSS with no build step, no dependency, no request beyond the gist and `config.json`, and the same data (W01's schema is unchanged).

## Tests
- `site/test/design.test.mjs` (new, `node:test`, no packages, run by `site/site.test.sh`) reads `site/style.css` and `site/index.html` as text and renders the views from W03's fixture data (built by `site.py build`, as `site/test/helper.mjs` does). It covers:
  - the tokens and themes: the custom properties, both themes, the absence of colour literals elsewhere, and the state colours;
  - contrast: the WCAG 2 contrast ratio of each pair in change 2, computed from the tokens' values in each theme;
  - the shell, the repository cards, the throttle meters and chart, the activity timeline and the badges, rendered to HTML strings;
  - the change mark, with a fake clock and two successive data sets;
  - the narrow layout's rules and the table wrappers;
  - the page's head and that nothing is loaded from another origin.
- The existing tests in `site/test/` (W03, W04, W05) keep running. A test may change only where it pins markup this node replaces, keeping the property it checks.

## Changes
1. **Tokens and themes.** `site/style.css` declares every colour once, as a custom property on `:root`. It declares them again in a `@media (prefers-color-scheme: dark)` block, which redefines every colour property. These are the page background, the surfaces (cards, panels, table headers), the borders, the text, the muted text, the links, the accent, the stale and held warnings, and one `--state-<state>` per state the explorer colours (`merged`, `running`, `failed`, `question`, `answered`, `waiting-pr`, `pr-open`, `ready`, `held`, `waiting`), plus `--state-other` for any other state. No colour literal (hex, `rgb()`, `hsl()` or a named colour other than `transparent` and `currentColor`) appears in `style.css` outside these declarations. None appears in the markup that `site/views.js`, `site/explorer/view.js` and `site/app.js` produce either: they use the properties. The explorer's node fill and legend swatch, the node table's state badge and the repositories view's state bar all take a state's colour from its one `--state-<state>`. Spacing, radii and type sizes are custom properties too, and every view uses the same ones. *W06-AC-1.*
2. **Contrast.** In both themes, each of these pairs has a contrast ratio of at least 4.5:1 (WCAG 2): the text and the muted text on the background and on the surfaces, the links on the background, the warning text on the background, the explorer's node label on every `--state-*` colour, and each badge's text on its background. *W06-AC-2.*
3. **The page shell.** Every view, including the setup help and the not-found page, renders inside one shell. Its header holds the site's name, the navigation and the data's age. The navigation link of the current route carries `aria-current="page"` (the repositories link on a repository's page). The ages keep W03's texts (`updated <n> minutes ago`, `seen <n> minutes ago`) and its `data-stale`, in a pill marked `data-live="fresh"` with a dot when the data is not stale, and `data-live="stale"` with the word `stale` when it is. W03's backoff and schema notices show as a banner under the header. `site/index.html` has a `theme-color` meta for each colour scheme and an inline SVG favicon (a `data:` URI). Neither it nor `style.css` loads a font, image, stylesheet or script from another origin. *W06-AC-3.*
4. **Repository cards.** The repositories view shows one card per repository (`data-card="<owner>/<name>"`). The card links to the repository's page and shows its loop state as a badge: `running`, `idle`, or `STOP requested`. It shows `<merged> of <total> merged` and a bar of node states, with one segment per state present, in the explorer's colour. A segment's width is its count's share of the total, as a percentage to one decimal, and its title is `<count> <state>`. A repository with no nodes says `no nodes` and has no bar. *W06-AC-4.*
5. **Throttle.** Each window is a meter: a `<meter>` element, or an element with `role="meter"` and `aria-valuenow`, at its utilization, with the percentage as text. A window without a utilization says `n/a` and has no meter. Next to W03's UTC reset time, the window shows a countdown, `resets in <h> h <m> min` (or `<m> min` under an hour). It is computed from the page's clock, so it moves without a request. Held or open is a badge in the warning or the state colour, with the reason. The history stays one inline SVG. It gains horizontal grid lines labelled `0%`, `50%` and `100%`, and a filled area under the line, both in token colours. *W06-AC-5.*
6. **Activity and repository details.**
   - The activity view's events are a timeline grouped by day. A heading names each date that the events' `time` falls on, newest first, and keeps W03's order within it.
   - The open PRs' mergeable states, the triage issues' states, and the repository view's loop and `STOP` states are badges (`data-badge="<value>"`).
   - The node table's state is a badge in the state's colour, followed by W03's details.
   - The repository filter of the activity view marks the current choice with `aria-current="true"`.
   - The explorer's edges, outlines, band labels and details panel take their colours from the tokens, so it reads in both themes.

   *W06-AC-6.*
7. **The change mark.** When a poll brings new data, the page marks what changed since the data before it, for 2 minutes by the page's clock. Activity events not in the previous data (compared by time, repository and text) are marked. So are the node table rows and explorer boxes of nodes whose state differs from the previous data, and the cards of repositories whose loop state or counts changed. Each mark is `data-new="true"`. The first data the page loads marks nothing. A 304 changes no mark. `style.css` animates the mark only inside `@media (prefers-reduced-motion: no-preference)`, and without that the mark is a static outline. The views stay pure functions: the previous data and the time it was replaced come in through `ctx`. *W06-AC-7.*
8. **Narrow screens.** Below a width of 40rem the header's navigation wraps, the cards stack in one column, and the explorer's details panel goes under the drawing. Every `<table>` the views render sits in a horizontally scrolling wrapper (`.table-scroll`), so the page itself never scrolls sideways. `site/index.html` keeps its `viewport` meta. *W06-AC-8.*
9. **Nothing else changes.** The data, routes, poller, links and escaping stay as W03, W04 and W05 made them. `site/package.json` gains no dependency, nothing needs a build step, and `.github/workflows/pages.yml` is unchanged. *W06-AC-9.*
10. **How it looks.** The PR records screenshots of the repositories, throttle, activity and repository views, and of the explorer with a node selected. They come from the fixture data, in the light and the dark theme, at 1280 and 390 pixels wide. They are taken with a headless browser the session installs outside the repository. Where the session cannot get one, the PR says so and lists those views for the owner to look at after the first Pages deploy. *W06-AC-10.*

## Risks
- The look is the owner's to judge, and no test checks pixels. The tests check the structure, the tokens and the contrast, and the screenshots are the only picture of it before the Pages deploy. The owner should look at them, and at the live page once, before merging.
- Contrast is computed from the tokens, not from the rendered page. A rule that puts text on a surface of change 2's list of pairs does not cover (an SVG label on a band, say) is unchecked.
- The colours stay chosen for state, not tested for colour blindness, as in W04. The legend, the badges and the details name every state in text.
- The change mark compares with the previous data the page holds. A tab that was hidden for an hour marks everything that changed in that hour at once, and a reload marks nothing.
- Pinning markup in W03's and W04's tests limits this node. Where a test pins an element this design replaces, changing the test is the node's judgment and the reviewer's to check. That is why W06-AC-9 has the PR list each change.
- The page is redrawn by replacing its HTML (`app.js`). An animation restarts on each redraw, so the mark's animation has to suit a page redrawn once a minute, when the ages change.
