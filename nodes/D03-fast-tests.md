**Resolves:** #68

## Purpose
After this node `make test` takes under three minutes on the scheduler's machine instead of about ten, which also leaves the self-deploy's `timeout 600` a wide margin. No criterion's check is lost: the time comes out of how the tests wait, how fast their fakes run, code copied between and within files, and cases that make the same checks twice, never out of what is checked. A runner prints each test file's time and flags a slow one, and CI fails a run over its budget, so the suite stays fast as nodes add tests.

## Tests
- `scheduler/runtests.test.sh` (new): runs `scheduler/runtests.sh` on fake test files in a scratch folder (one that passes at once, one that fails, one that sleeps past a small budget, two that write to their output while running at the same time) and checks its output, its exit status and that every file ran.
- The existing `*.test.sh` files (changed only as Changes 3 to 6 allow): every case that passes on the node's base still passes, or its checks are made by the case it was merged into.
- The recorded runs in the PR: `make test` on the node's base and on its head on the scheduler's machine, each with the runner's per-file times (the base's from the same runner), and the sorted `PASS:` lines of both and their diff.

## Changes
1. **A test runner.** `scheduler/runtests.sh <file>...` runs each test file with the interpreter the `Makefile` uses for it today (`bash` for `loop.test.sh`, `sh` for the rest), up to `TEST_JOBS` files at once (default twice the number of CPUs, since the files mostly wait), keeping each file's output and printing it whole when the file ends, so outputs never interleave. After each file it prints `TIME <seconds> <file>`, and `SLOW: <file> took <seconds>s, budget <n>s` for a file over `TEST_FILE_BUDGET` seconds (default 30); at the end, `TOTAL <seconds>` and `SLOW: total ...` when over `TEST_BUDGET` (default 180). It runs every file even when one fails. It exits non-zero when any file failed; with `TEST_BUDGET_ENFORCE=1` it also exits non-zero when a file or the total was over budget; without it, time never fails the run. *D03-AC-4.*
2. **The `Makefile` and CI use it.** `make test` runs `scheduler/runtests.sh` with every test file of today's target and `scheduler/runtests.test.sh`; a new test file is added to that list. `.github/workflows/test.yml` runs `make test` with `TEST_BUDGET_ENFORCE=1`, `TEST_FILE_BUDGET=60` and `TEST_BUDGET=360` (twice the local defaults, for a slower runner). `deploy.sh`'s `make test` sets none of them, so a slow machine never rejects a deploy for its time alone. *D03-AC-4, D03-AC-5.*
3. **Tests wait for what they check.** A fixed `sleep` before a check, or a wait for a number of loop ticks, becomes a wait until the condition the next check reads holds (a status-log line, a file, a process gone), with a timeout no shorter than the old wait. A check that something did not happen waits until the loop's tick has visibly passed the needed number of times (the loop's `heartbeat` file, or a status-log line it writes each tick) instead of a fixed time. A fixed sleep remains only where no condition can be observed, with a comment that says why. *D03-AC-1, D03-AC-3.*
4. **Fakes run fast.** A fake (`gh`, `claude`, `tmux` and the like) gives the same answers to the same calls in less time: for example, `report.test.sh`'s fake `gh` stops loading and rewriting its whole JSON file on every call where that is not what a case checks, or one long-lived fake serves the calls. *D03-AC-1, D03-AC-3.*
5. **No copied code.** Helpers, fakes and setup copied between or within test files (the `within`/`count`-style waits, the fake `gh` and `claude`, the rate-limit event writers, the scratch remotes and checkouts) move into shared files under `scheduler/testdata/lib/`, which the test files source. A large file may be split into several files that run at once under the runner. *D03-AC-1, D03-AC-3.*
6. **No overlapping cases.** A case whose every check another case also makes (the same command on the same state, and the same expected output) is merged into that case or removed. Each one is a row of the PR's overlap table: the case's name, the case that now makes its checks, and why they are the same. No case is removed for any other reason. *D03-AC-2, D03-AC-3.*
7. **`AGENTS.md` says how.** The `make test` line gives the suite's time and the runner; the Tests bullet says that a new case waits for the condition it checks (no fixed sleep where a condition can be observed), uses the shared helpers and keeps its file under `TEST_FILE_BUDGET`. The rule for frozen test lines is unchanged: changes 3 to 6 are allowed for this node by this spec only. *D03-AC-6.*

## Risks
- Files running at once share the machine, and some cases look for processes by their command line (`pgrep -f`); a pattern that is not unique to its file's scratch folder could match another file's loop. The node keeps each such pattern under its own `mktemp` folder, or runs that file alone.
- A wait for a condition with a long timeout passes as soon as the condition holds; a broken loop now fails at the timeout instead of at the next check, so a failing run can take longer than a passing one.
- A check that something did not happen is only as strong as the ticks it waits for: waiting for fewer ticks than the old fixed sleep covered weakens it. The tick count stays at least what the old sleep allowed.
- The nodes not built yet add cases to `loop.test.sh` and `report.test.sh`; whichever merges second resolves the conflict, and a new case written in the old style shows up in the runner's `TIME` lines and, past the budget, fails CI.
- CI runners vary in speed; the doubled budgets in CI are a guess until the node's own CI run records the times.
