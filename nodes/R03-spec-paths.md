## Purpose
After this node one rule decides which files are a repository's spec files, and every tool that asks uses it: the role guard, `check-spec-diff.py` and `owns.regime_files` (with the coverage, ownership and inventory checks that call it). A path is a spec file when the **Spec files:** line of `AGENTS.md`'s "Building a node" section or `.noodlebot/roles.yaml`'s `specs:` names it, each read at the commit being judged, and `AGENTS.md` read through a symlink as the guard reads it in the working tree; a repository with neither gets the default `SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `docs/graph.yaml`, `nodes/`. So the guard and the spec-diff check can no longer disagree, as they did over `AGENTS.md` in bosnia's R04 (tuckermclean/bosnia#41), where no role could commit the node's change and a spec PR changing `AGENTS.md` failed the check. This repository's **Spec files:** line gains `AGENTS.md` and `CLAUDE.md`, and adopt's drafted line names `AGENTS.md`, so the guard keeps protecting them here and in newly adopted repositories. The node skill says who commits a node's change to `AGENTS.md` or `CLAUDE.md`: a spec PR, or, when the file is on the list and in the node's **Owns:**, the orchestrator's own `spec(<ID>): ...` commit; when it is not on the list, the implementer, test-first.

## Changes
1. **One rule.** `plugin/skills/node/spec_files.py` (standard library plus the YAML reader the guard already uses) holds the default list `SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `docs/graph.yaml`, `nodes/` and one function that, given the text of `AGENTS.md` and of `.noodlebot/roles.yaml` (either may be missing), returns the spec entries: the backticked paths on the **Spec files:** line of the "Building a node" section (one physical line, read as `check-spec-diff.py` reads it today) together with the `specs:` globs of `roles.yaml`; the default only when neither names any. A second function says whether a root-relative path is a spec file, matching each entry with `owns.match` and no file list: a trailing `/` means the folder and everything under it, `*` and `**` are wildcards, and anything else is a literal path (so `?` is a literal character). A third reads `AGENTS.md` at a commit: when `AGENTS.md` there is a symlink (mode 120000) to a file in the repository, it returns that file's text at the same commit, as the guard's read of the working tree follows the link; a link that leaves the repository or names no file at that commit reads as a missing `AGENTS.md`. A `roles.yaml` that is not a mapping, or whose `specs:` is not a list of strings, is an error the caller reports. *R03-AC-1.*
2. **Every classifier calls it.** `guard.py` takes its `specs` paths from the shared rule, reading `AGENTS.md` and `.noodlebot/roles.yaml` from the repository root's working tree; its `tests:` key, its other role rules and its blocking of a malformed `roles.yaml` are unchanged, and the implementer still may not write `.noodlebot/roles.yaml`. `check-spec-diff.py` reads both files at `<from>` (`AGENTS.md` through a symlink, Change 1), so a branch cannot widen either list. Its output keeps its shape: line 1 is `spec files: <list>` and line 2 is the `from:` line, which names the sources used (`AGENTS.md at <from>`, `.noodlebot/roles.yaml at <from>`, or both) and, when neither list names a path, still starts `from: default`, as the loop's spec-PR scope check (`spec_scope` in `scheduler/loop.sh`) and the frozen `nl` case of `scheduler/loop-g05.test.sh` read it; `--allow` still adds a path for one run, and a `roles.yaml` at `<from>` it cannot read exits 2 with the reason on stderr and nothing on stdout. `owns.regime_files` gains the `roles.yaml` text as an optional argument and returns the shared rule's spec files plus `AGENTS.md` and `.noodlebot/roles.yaml`; `check-coverage.py` and `check-owns-diff.py` read `AGENTS.md` (through a symlink) and `roles.yaml` at the commit they judge, and `inventory.py` passes `roles.yaml` from the working tree it reads. None of these files keeps a spec-path list of its own. *R03-AC-1, R03-AC-2, R03-AC-3.*
3. **The node skill says where a change to a spec-listed file goes.** The **Role agents** paragraph and step 7's "A spec PR changes only the repository's spec files" paragraph of `plugin/skills/node/SKILL.md` describe the shared rule (the line and `roles.yaml` `specs:` together, else the default with `AGENTS.md` and `CLAUDE.md`) instead of the old default. 4. **Adopt drops `--allow AGENTS.md` and drafts a line that names it.** Every spec-diff check in `plugin/skills/adopt/SKILL.md` runs without `--allow AGENTS.md`, since `AGENTS.md` is in the default when `origin/main` has neither list; `--allow .noodlebot/roles.yaml` stays where section 3 drafted that file. ## Risks
- The guard now follows a repository's **Spec files:** line, so where that line leaves out `AGENTS.md` or `CLAUDE.md` the guard stops protecting them from the tester and implementer, which until now came from the guard's own default. This repository (`AGENTS.md`, `CLAUDE.md`) keeps them guarded through Change 7 in this node; tuckermclean.com (`AGENTS.md`) loses it until its follow-up puts `AGENTS.md` on its line; bosnia (`AGENTS.md`) loses it until bosnia's R04 (tuckermclean/bosnia#51) does. A repository with neither list (an adoption before its first spec PR merges) now treats both as spec files everywhere, in `check-spec-diff.py` and `owns.regime_files` too.
- A repository whose `.noodlebot/roles.yaml` names `specs:` but whose `AGENTS.md` has no line the checker reads (rl144 today, whose line sits behind a symlink) gets `from: default` from the checker now, so the loop's spec-PR scope check only logs a spec PR there that changes other files. After this node its `from:` line names `roles.yaml`, so the loop sends such a spec PR back (`SPEC-PR-SCOPE`) where today it logs one line.
- The guard reads both lists from the working tree, so a role that may write `AGENTS.md` (in a repository whose line leaves it out) could edit the line and change what the guard protects in that session; the checker reads `<from>` and is not fooled, and the reviewer sees the diff.
- Matching by `owns.match` makes `?` a literal character in a `roles.yaml` glob, where the guard treated it as one character; no list in this repository or its fixtures uses `?`. A wildcard-free entry without a trailing `/` stays a literal path, as `check-spec-diff.py` read it, where `owns.match` with a file list would have read a folder.
- `check-spec-diff.py` now reads YAML when `<from>` has a `roles.yaml`; a machine without the YAML reader the guard uses makes it exit 2 there, never 1.
- G05-AC-1's default list and this repository's line, and G05-AC-4's `--allow AGENTS.md`, are superseded by this node's criteria; G05's spec is history and is not edited.
- The orchestrator's `spec(<ID>): ...` commit to an owned spec-listed file, this node's own change to `AGENTS.md` included, is not test-first; the fresh review and the PR's listing are its only check.
