## Purpose
After this node one rule decides which files are a repository's spec files, and every tool that asks uses it: the role guard, `check-spec-diff.py` and `owns.regime_files` (with the coverage, ownership and inventory checks that call it). A path is a spec file when the **Spec files:** line of `AGENTS.md`'s "Building a node" section or `.noodlebot/roles.yaml`'s `specs:` names it, each read at the commit being judged; a repository with neither gets the default `SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `docs/graph.yaml`, `nodes/`. So the guard and the spec-diff check can no longer disagree, as they did over `AGENTS.md` in bosnia's R04 (tuckermclean/bosnia#41), where no role could commit the node's change and a spec PR changing `AGENTS.md` failed the check. The node skill says who commits a node's change to `AGENTS.md` or `CLAUDE.md`: a spec PR, or, when the file is on the list and in the node's **Owns:**, the orchestrator's own `spec(<ID>): ...` commit; when it is not on the list, the implementer, test-first.

## Tests
- `plugin/skills/node/spec-files.test.sh` (new): fixture repositories (`git init` in a scratch folder) in four configurations: neither list; only a **Spec files:** line; only a `.noodlebot/roles.yaml` with `specs:`; both, naming different paths. For each, a table of paths that are not test paths (`SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `docs/graph.yaml`, `docs/other.md`, `nodes/N01-x.md`, `nodes/sub/deep.md`, `scripts/run.sh`, a path only the line names, a path only a `roles.yaml` glob with `*` or `**` matches, a path whose name holds a literal `?`) is classified three ways: `check-spec-diff.py` on a branch that changes that one path (exit 0 or `NOT SPEC <path>` with exit 1), `guard.py --role implementer --kind write` on that path (blocked as a spec path, or allowed), and `spec_files.py` directly. The three agree on every path, and each agrees with the expected union-or-default rule. Further cases: a branch that adds a path to `roles.yaml`'s `specs:` or to the line is judged by the lists at `<from>`; a malformed `roles.yaml` at `<from>` makes the checker exit 2 with nothing on stdout, and makes the guard block role writes as before; the `from:` line names each source used; `--allow` still adds a path; `owns.regime_files` returns the shared rule's spec files plus `AGENTS.md` and `.noodlebot/roles.yaml` in each configuration; `guard.py`, `check-spec-diff.py` and `owns.py` hold no spec-path list of their own.

## Changes
1. **One rule.** `plugin/skills/node/spec_files.py` (standard library plus the YAML reader the guard already uses) holds the default list `SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `docs/graph.yaml`, `nodes/` and one function that, given the text of `AGENTS.md` and of `.noodlebot/roles.yaml` (either may be missing), returns the spec entries: the backticked paths on the **Spec files:** line of the "Building a node" section (one physical line, read as `check-spec-diff.py` reads it today) together with the `specs:` globs of `roles.yaml`; the default only when neither names any. A second function says whether a root-relative path is a spec file, matching each entry with `owns.match` and no file list: a trailing `/` means the folder and everything under it, `*` and `**` are wildcards, and anything else is a literal path (so `?` is a literal character). A `roles.yaml` that is not a mapping, or whose `specs:` is not a list of strings, is an error the caller reports. *R03-AC-1.*
2. **Every classifier calls it.** `guard.py` takes its `specs` paths from the shared rule, reading `AGENTS.md` and `.noodlebot/roles.yaml` from the repository root's working tree; its `tests:` key, its other role rules and its blocking of a malformed `roles.yaml` are unchanged, and the implementer still may not write `.noodlebot/roles.yaml`. `check-spec-diff.py` reads both files at `<from>`, so a branch cannot widen either list; its `from:` line names the sources used (`AGENTS.md at <from>`, `.noodlebot/roles.yaml at <from>`, or the default), `--allow` still adds a path for one run, and a `roles.yaml` at `<from>` it cannot read exits 2 with the reason on stderr and nothing on stdout. `owns.regime_files` gains the `roles.yaml` text as an optional argument and returns the shared rule's spec files plus `AGENTS.md` and `.noodlebot/roles.yaml`; `check-coverage.py`, `check-owns-diff.py` and `inventory.py` pass `roles.yaml` as it is at the commit they judge. None of these files keeps a spec-path list of its own. *R03-AC-1, R03-AC-2, R03-AC-3.*
3. **The node skill says where a change to a spec-listed file goes.** The **Role agents** paragraph and step 7's "A spec PR changes only the repository's spec files" paragraph of `plugin/skills/node/SKILL.md` describe the shared rule (the line and `roles.yaml` `specs:` together, else the default with `AGENTS.md` and `CLAUDE.md`) instead of the old default. A new paragraph says, naming `AGENTS.md` and `CLAUDE.md`: a change to a file on the spec list goes in a spec PR; when the node's **Owns:** names such a file, the orchestrator commits the node's change to it on the node branch as a commit of its own (`spec(<ID>): ...`) after the RED commit, lists it in the PR, and the fresh reviewer reviews it with the node; the guard does not change for it. A file not on the list (such as `AGENTS.md` in a repository whose line leaves it out) is written by the implementer, test-first, like any other owned file. *R03-AC-4.*
4. **Adopt drops `--allow AGENTS.md`.** Every spec-diff check in `plugin/skills/adopt/SKILL.md` runs without `--allow AGENTS.md`, since `AGENTS.md` is in the default when `origin/main` has neither list; `--allow .noodlebot/roles.yaml` stays where section 3 drafted that file. The sentences that say both files are outside the default list say that only `roles.yaml` is. *R03-AC-5.*
5. **The role agents name the shared list.** In `plugin/agents/tester.md` and `plugin/agents/implementer.md`, the line listing what they never edit names the repository's spec files (the shared rule's list) and `.noodlebot/roles.yaml` instead of a fixed `SPEC.md`, `docs/graph.yaml`, `nodes/`, `AGENTS.md`. In this repository's `.claude/agents/noodlebot-tester.md` and `.claude/agents/noodlebot-implementer.md` the same line names the spec files of `AGENTS.md`'s **Spec files:** line and keeps `.claude/`, so an implementer here may write `AGENTS.md` and `CLAUDE.md`, which this repository's line leaves out. *R03-AC-5.*
6. **The frozen lines that encode the old default.** The owner's decision on issue #253 (Q1 a: the default includes `AGENTS.md` and `CLAUDE.md`, and adopt's `--allow AGENTS.md` is dropped) contradicts three frozen checks, and only these change: in `plugin/skills/node/check-spec-diff.test.sh`, the case "a branch adding the line is judged by the list at <from>" now expects only `NOT SPEC scripts/run.sh` (`AGENTS.md` is in the default), and the case "without --allow, AGENTS.md is outside the default list" now expects exit 0 with no `NOT SPEC` line; in `plugin/skills/adopt/adopt.test.sh`, G05-AC-4's check that adopt runs the checker with `--allow AGENTS.md` becomes a check that it runs it without. The PR lists each changed frozen line (file, base line, before and after) and quotes the owner's decision, for the owner's approval as the node skill's frozen-line rule asks. *R03-AC-6.*

## Risks
- The default now includes `AGENTS.md` and `CLAUDE.md` for `check-spec-diff.py` and `owns.regime_files` too. A repository with neither list (an adoption before its first spec PR merges) now treats both as spec files everywhere; one whose **Spec files:** line leaves them out, such as this repository, keeps its behaviour in the checker and loses the guard's protection of them, which until now came from the guard's own default.
- The guard reads both lists from the working tree, so a role that may write `AGENTS.md` (in a repository whose line leaves it out) could edit the line and change what the guard protects in that session; the checker reads `<from>` and is not fooled, and the reviewer sees the diff.
- Matching by `owns.match` makes `?` a literal character in a `roles.yaml` glob, where the guard treated it as one character; no list in this repository or its fixtures uses `?`. A wildcard-free entry without a trailing `/` stays a literal path, as `check-spec-diff.py` read it, where `owns.match` with a file list would have read a folder.
- `check-spec-diff.py` now reads YAML when `<from>` has a `roles.yaml`; a machine without the YAML reader the guard uses makes it exit 2 there, never 1.
- G05-AC-1's default list and G05-AC-4's `--allow AGENTS.md` are superseded by this node's criteria; G05's spec is history and is not edited.
- The orchestrator's `spec(<ID>): ...` commit to an owned spec-listed file is not test-first; the fresh review and the PR's listing are its only check.
